# 내보내기와 LLM 전달

## Decisions

- 변환 결과의 내보내기 동작은 결과 머리(제목·저자 아래)의 툴바에 둡니다. 순서는 복사하기, `.md` 다운로드, ChatGPT로 열기, Claude로 열기이고, 그 아래에 프롬프트 선택이 옵니다.
- ChatGPT·Claude로 넘길 때는 내용 길이로 경로를 고릅니다. 프롬프트와 본문을 합쳐 인코딩한 URL이 8,000자 이하면 `chatgpt.com/?q=`, `claude.ai/new?q=`에 채워 새 탭으로 엽니다. 그보다 길면 같은 내용을 클립보드에 복사하고 빈 새 대화를 연 뒤, 붙여넣으라는 안내를 보여 줍니다.
- 프롬프트는 프리셋 3종(요약해줘, 한국어로 번역해줘, 쉽게 설명해줘)과 직접 입력 중 하나를 고르고, 기본은 선택 없음입니다. 프롬프트는 ChatGPT·Claude로 열 때만 본문 앞에 빈 줄 하나를 두고 붙습니다. 복사하기와 `.md` 다운로드에는 본문만 담깁니다.
- 직접 입력한 프롬프트는 저장하지 않습니다. 새로고침, 다른 프롬프트 선택, 새 변환, 지우기를 하면 사라집니다.

## Boundaries

- 전달 대상은 ChatGPT와 Claude 두 곳뿐입니다. 다른 LLM 서비스를 막는 결정은 아니지만, 추가하면 같은 길이 분기를 따라야 합니다.

## Why

짧은 글은 클릭 한 번으로 끝나야 하고, 긴 글도 잘리지 않고 넘어가야 합니다. 두 조건을 한 경로로는 맞출 수 없어서, 사용자가 길이에 따른 분기를 골랐습니다. 툴바 위치는 변환 직후 가장 먼저 눈에 들어오고 휴대폰에서도 본문을 가리지 않는 자리입니다. 직접 입력은 요구 사항에서 1회용으로 정했습니다.

## Reconsider when

- ChatGPT나 Claude가 `?q=` 프롬프트 채우기를 바꾸거나 없애면, 짧은 글도 클립보드 경로로 보냅니다. 이 채우기는 공식 계약이 아닙니다.
- 실제 사용에서 8,000자 근처 URL이 어느 한 서비스에서 잘리거나 열리지 않으면 한도를 서비스별로 낮춥니다.

## Still-rejected alternatives

- 항상 클립보드로 넘기기: 짧은 글도 매번 붙여넣어야 해서 클릭 한 번으로 끝나지 않습니다.
- 항상 URL로 넘기기: 긴 글이 URL 길이 한도에서 잘립니다.
- 내보내기를 하단 고정 바나 오른쪽 사이드 패널에 두기: 사용자가 세 안을 프로토타입으로 비교한 뒤 결과 위 툴바를 골랐습니다. 툴바는 변환 직후 가장 먼저 눈에 들어오고 휴대폰에서도 본문을 가리지 않습니다.

## Evidence worth preserving

- 자동화 브라우저(agent-browser, headless Chrome)로 `chatgpt.com`, `claude.ai`를 열면 Cloudflare 사람 확인 화면이 떠서 입력창이 실제로 채워졌는지는 자동으로 확인할 수 없습니다. 이 부분은 사람이 자기 브라우저에서 확인해야 합니다.
